# Создание CV из резюме HH

## Назначение
Преобразуй резюме HH в локальный автономный HTML на русском, сохраняя содержание и привычную компоновку. Пользовательские правки текущей задачи имеют приоритет. Скилл сохраняет правила оформления, а не персональные данные конкретного кандидата.

## Исходник и извлечение
- Читай последнюю указанную версию; исходник сохраняй неизменным. Конвертация не означает разрешение переписывать достижения, даты, должности или метрики.
- Проверяй фактический формат: файлы .doc из HH могут быть RTF (начинаются с `{\rtf`). Не передавай их напрямую DOCX-парсеру.
- Для DOCX/PDF используй подходящие средства извлечения и просмотра; для документов и runtime при необходимости подключай доступные профильные навыки и bundled dependencies.
- На Windows RTF можно читать через System.Windows.Forms.RichTextBox без открытия окна. Сохраняй промежуточный UTF-8 текст в рабочей папке. При блокировке исходника допустима read-only копия с FileShare.ReadWrite, затем разбирай копию. Не закрывай чужие приложения и не изменяй исходник.
- Сохраняй разрывы абзацев и ручные переводы строк (в RTF могут извлекаться как U+000B), таблицы дат и описаний, маркированные списки. Удаляй из видимого текста служебные коды HYPERLINK, оставляя рабочие ссылки.

## Оформление HTML
Используй [assets/cv.css](assets/cv.css) как основу, а [assets/details.html](assets/details.html) — как пример раскрывашки. Это проверенный визуальный стиль; адаптируй под длину содержания.
- Один UTF-8 HTML с CSS и небольшим JS внутри, без CDN, внешних шрифтов, трекеров или сетевых зависимостей. Кликабельные контакты разрешены.
- Светлый лист шириной около 1000 px, Arial, спокойная чёрно-серая типографика, тонкие разделители. Сохраняй порядок исходных разделов; не добавляй декоративный брендинг.
- Имя сверху. Под ним два столбца: слева все контакты (телефон, почта, Telegram, другие профили); справа личные данные: «Пол: мужской/женский» при наличии в исходнике, город проживания, гражданство/разрешение на работу, переезд/командировки. Не добавляй отсутствующие сведения. На узком экране столбцы идут последовательно.
- В строке телефона автоматически убирай служебную фразу HH «— предпочитаемый способ связи» и связанный разделитель «•». Для согласованного формата используй «+7 (…) … (звонки, Telegram, WhatsApp)»: телефон остаётся ссылкой tel. Сохраняй только указанные в исходнике или подтверждённые пользователем мессенджеры; не добавляй их по умолчанию. Не переноси предпочтения владельца скилла на других кандидатов. Подписи не дублируй при повторных правках.
- Перед адресом электронной почты добавляй подпись «Почта:», сохраняя кликабельную ссылку mailto. Не дублируй подпись, если она уже есть.
- Если гражданство ровно «Россия», удали из этой же строки повторное «, есть разрешение на работу: Россия». При другом гражданстве сведения о разрешении на работу сохраняй. Не удаляй разрешения для иных стран и не делай выводов о гражданстве из языка или имени.
- Заголовок «Желаемая должность», без «и зарплата». Под ним целевая должность из исходника.
- Удали логотип HH. По умолчанию убери «Специализации», тип занятости, формат работы и время в пути — это согласованный компактный формат. Не удаляй соответствующие ограничения о переезде/командировках из правого столбца.
- Места работы: слева период и длительность, справа компания, должность, описание и достижения. Сохраняй все даты и числа. На мобильном период помещается над описанием.
- Удали отдельный блок тегов «Навыки»; сохраняй языки в разделе «Знание языков» и компетенции в «Обо мне». Не вырезай упоминания технологий из опыта. Если пользователь явно просит оставить теги, разделяй их запятыми. Не разделяй слова внутри «Управление требованиями», REST API и т.п.; в экспорте между словами может быть неразрывный пробел.
- Образование остаётся открытым. Курсы — в закрытом по умолчанию разделе «Повышение квалификации».

## Какие места работы сворачивать
- По умолчанию оставь открытыми 2–3 последних работодателя; остальные помести в одну раскрывашку «Предыдущий опыт работы». Оцени объём: обычно два при очень подробных последних местах, три при коротких. Явный выбор пользователя важнее.
- Если последние 2–3 места короткие и вместе охватывают менее пяти календарных лет, оставь открытыми все места, относящиеся к последним пяти годам, а более ранние сверни. Граница считается от актуальной даты задачи, не по сумме стажа и не от даты начала самого старого места.
- Место, пересекающее пятилетнюю границу, оставь открытым целиком. Не разрезай его на две записи, не меняй даты и не дублируй. При малом общем стаже раскрывашка может не понадобиться.
- Внутренние проекты и повышения не считай отдельными работодателями. Сохраняй их внутри общего блока компании.

## Заметные раскрывашки
Используй нативные details/summary, закрытые при первом открытии HTML.
- Вся строка summary кликабельна: светло-голубой фон, рамка, контрастный шеврон, название и подпись количества («4 места работы», «6 курсов» — вычисляй фактически).
- Справа видимая надпись «Развернуть», при открытии — «Свернуть». Шеврон также меняет направление. Нужны hover и видимый keyboard focus.
- Обе подписи могут находиться в DOM, но скрытая не должна занимать место. Открытие работает клавиатурой и без JS.
- Перед печатью раскрывай все details, после печати восстанавливай их предыдущее состояние. В печатном виде убирай цветные подложки и надписи управления, сохраняя заголовки и полный текст.

## Проверка и сохранение
- Сверь текст источника и HTML с учётом только разрешённых удалений, нормализации пробелов и маркеров списков. Проверь, что не потерялись работы, достижения, курсы, цифры и контакты.
- Открой HTML в доступном браузерном средстве, проверь скриншот широкого и узкого экрана. Проверь раскрытие и сворачивание обоих разделов, фактические количества, отсутствие горизонтальной прокрутки, расположение контактов и печать.
- После правок обновляй существующий HTML. Промежуточные скрипты и снимки храни в рабочей папке, не в пользовательском наборе документов.
- Сохраняй результат в согласованную пользователем папку и выдавай доступную ссылку на файл. Если для интерфейса нужна копия в outputs, синхронизируй обе копии. Не публикуй CV в интернете без отдельного запроса.
- В конце кратко сообщи, что изменилось. Содержательные замечания к резюме не применяй в процессе конвертации молча.
